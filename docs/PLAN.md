# 鬼宅（暂名）：《山中小屋》式在线桌游开发计划

> 依据：`research-rules.md`（规则）、`research-cloudflare.md`（平台）。前项目 `../magical_athlete` 的账号、大厅、房间、断线重连、部署方式可以直接复用。
> 目标：3–6 人在线合作 / 背叛探索桌游，规则框架取自《山中小屋》第 3 版，**内容全部原创**，跑在 Cloudflare Workers 免费计划上。

---

## 1. 范围

### 第一版要做
| 模块 | 内容 |
|---|---|
| 账号 / 大厅 / 房间 | 复用前项目：用户名密码 + 游客、房间列表实时推送、建房（3–6 人）、准备、换座、AI 补位、断线重连、托管 |
| 探索阶段 | 完整第 3 版流程：按速度移动、发现房间（抽板块、旋转对齐门、楼层限制、每层留口）、事件 / 物品 / 预兆、交易、特殊行动、房间效果 |
| 作祟检定 | 第 3 版（预兆数颗骰 ≥ 5，最后一张必触发）；第 2 版经典规则做成房间选项 |
| 作祟阶段 | 剧本卡 × 预兆查表定剧本和叛徒；双方只看到己方规则；执行过的规则自动公开到日志；战斗、怪物、眩晕、尸体搜刮、阻碍、视线、叛徒特权、胜负判定 |
| 内容（原创） | 12 名探险者（6 块双面板）、42 块房间 + 3 块起始板、9 预兆 / 22 物品 / 约 40 事件、5 张剧本卡、**首批 12 个剧本**（覆盖第 6.2 节的主要类型，含 1 个无叛徒、1 个隐藏叛徒） |
| AI | 探索阶段启发式 AI；作祟阶段由剧本给出 AI 提示（目标房间、优先行动），通用 AI 执行，能当英雄也能当叛徒 |
| 表现 | 俯视 2D 宅邸地图（三层切换、拖拽缩放）、房间翻开动画、骰子动画、属性轨 UI、卡牌弹出、阴森氛围音效与 BGM；手机可玩 |
| 部署 | `*.workers.dev` 先上线，之后用户自行换域名 |

### 暂不做
剩余 38 个剧本（DSL 稳定后陆续加）、观战、文字聊天（只做表情和快捷语）、战绩排行、多语言、扩展包内容。

## 2. 总体架构

```
浏览器 SPA（Vite + Preact + signals；@cloudflare/vite-plugin 同源开发）
   │ HTTPS /api/*      WSS /ws/lobby      WSS /ws/house/:id
   ▼
Worker 入口（路由、HMAC Cookie 鉴权、限流）
   ├─ 静态资源：前端、房间 / 卡牌美术、音频（免费，不计请求）
   ├─ D1：users、match_results
   ├─ LobbyDO（单例）：房间摘要 + 大厅推送
   └─ HouseDO（每局一个，SQLite）：权威状态 + 动作日志 + 单 alarm 计时 + AI + 按座位过滤视图
```

原则：
- **服务端权威**：骰子（种子 RNG）、洗牌、规则结算、AI 全在 HouseDO。客户端只发意图，按事件播动画。
- **规则引擎是纯 TS、确定性、无 I/O**：`Game.restore(config, actions)` 重放恢复，服务端、测试、本地模拟共用。
- **隐藏信息只有一个出口** `viewFor(state, seat)`：牌堆顺序、剧本号、叛徒身份、对方规则在作祟前后都只按座位下发。剧本文本放在 Worker 代码里，不进前端 bundle。
- 只有 `/api/*`、`/ws/*` 进 Worker，额度用完时页面照样能打开。

## 3. 规则引擎（核心）

### 3.1 状态
- `house`：三层（地下室 / 一楼 / 二楼）的网格，每格 `{tileId, rotation, tokens[]}`；三块起始板；远距相连表（楼梯、成对房间、传送房当前位置）。
- `decks`：板块堆（按背面楼层过滤、放牌堆底）、事件 / 物品 / 预兆堆。
- `players[]`：角色、四条属性轨下标、位置、手牌、本回合标记（已交易、已用行动、回合开始时的速度和手牌快照）、存活 / 尸体。
- `phase`：`explore` → `haunt-reveal` → `haunt` → `end`；`haunt` 下有剧本状态（计数轨、标记、怪物、旗标）。
- `pending`：当前等待的决策（谁、什么类型、可选项、截止时间）。

### 3.2 动作与决策
- 主动动作：`move{path}`、`explore{dir}`、`placeTile{rotation}`、`trade`、`useAbility`、`attack`、`specialAction`、`endTurn`。
- 被动决策（引擎暂停等玩家）：分配伤害、事件里的选择、是否发动可选效果、自愿当叛徒等。
- 移动只做合法性校验；客户端高亮可达房间，路径由服务端算最短可行路径（考虑阻碍）。

### 3.3 效果 DSL（物品、事件、房间、剧本共用）
数据化描述，配一个受限表达式语言，**不允许任意脚本**：
- **效果原语**（约 40 个）：`gainTrait / loseTrait / damage(type, n | dice) / heal / roll / branch(结果表) / moveTo / placeToken / removeToken / placeTile / findTile / drawCard / giveItem / discard / stun / kill / spawnMonster / advanceTrack / setFlag / reveal / endTurn …`
- **钩子**：`onDiscover / onEnter / onTurnStart / onTurnEnd / onRoundEnd / onDeath / onAttackResolved / onPickUp`
- **修改器**：改移动成本、改伤害类型、禁止进入某房间、怪物穿墙等，插进引擎的移动 / 伤害 / 探索计算。
- **剧本**：元数据（触发、叛徒规则、类型、人数缩放）、设置、修改器、钩子、特殊行动（条件、检定、成败效果）、怪物、双方胜利条件、AI 提示、双方文本（与逻辑分离）。
- 加载时用 schema 校验每个剧本；每个剧本有一条「AI 互打能结束」的冒烟测试。

### 3.4 测试
- 单元：属性轨（重复数值、critical 约束、作祟前不死）、地图放置（门对齐、每层留口、楼层用尽）、作祟概率、叛徒规则（同分、左侧）、战斗、阻碍、视线。
- 隐藏信息：随机对局中任意英雄视角的序列化结果不含叛徒专属字段，反之亦然。
- 冒烟：每个剧本 AI 互打几局能结束（遵照之前的偏好，不做大规模模拟）。
- 规则书没写清的地方记到 `rules-decisions.md`，代码里引用编号。

## 4. AI

- **探索阶段**：偏向去未探索的门口；按属性短板挑房间；物品交易给更合适的人；不主动进危险房间。
- **作祟阶段**：每个剧本给出 AI 提示（目标房间 / 目标标记 / 要护送或击杀的对象 / 特殊行动优先级），通用 AI 做「最短路过去 → 执行行动 → 打得过就打」。
- 怪物由叛徒（真人或 AI）控制；叛徒是 AI 时怪物也由 AI 走。
- 真人掉线超时由 AI 托管，重连后交回。
- 作祟阶段可能出现「全员 AI 当叛徒」的单人局，所以 AI 叛徒的目标同样走剧本提示。

## 5. 服务端

- **账号 / Lobby**：直接移植前项目 `auth.ts`、`lobby.ts`（PBKDF2 + HMAC Cookie、游客、限流）。
- **HouseDO**：
  - 小件状态（房间信息、计时、掉线表）用 `ctx.storage.kv`；对局用 `sql` 存「配置 + 动作日志分块 + 每回合快照」。一个请求只追加一行，控制行写入。
  - WebSocket Hibernation；attachment 存 `{userId, seat}`；心跳用 auto-response。
  - 每次状态变化：逐个连接 `viewFor` 后发送「视图增量 + 事件」。
  - 单 alarm 管理：行动超时（探索每回合 90 秒，可调）、AI 节奏、掉线宽限、空房回收。
  - 对局结束写 D1 `match_results`。
- **部署**：DO 默认推迟更新，局中发版通常不断线；客户端仍保留指数退避重连和快照恢复。

## 6. 前端

### 6.1 技术栈
Preact + signals；地图用 **SVG**（板块是 `<g>`，旋转、翻开动画用 CSS transform），不上 three.js；拖拽缩放自写。Vite 拆包，进对局才加载地图和美术。
预算：大厅首屏 JS ≤ 40 KB gz；对局 JS ≤ 120 KB gz；全部资源 ≤ 3 MB（程序化美术为主）。

### 6.2 页面
1. 登录 / 注册 / 游客
2. 大厅：房间卡片、建房（人数、规则模式、剧本卡选择或随机、AI 难度）
3. 房间：座位、选角色（双面板互斥）
4. **对局**：中间是宅邸地图（楼层页签 + 小地图）；底部是自己的属性轨和手牌；侧边是玩家列表和行动日志；当前决策用浮层（选门、旋转板块、分配伤害、事件结果）。
5. **作祟揭晓**：全屏过场（预兆、揭示者、叛徒是谁）→ 公开引言 → 各自的「秘密规则」面板（只对己方可见，可随时翻看）
6. 结算：胜方、关键事件回放、再来一局
7. 图鉴：房间 / 卡牌 / 探险者 / 已玩过的剧本

### 6.3 美术与音效
- 风格：维多利亚哥特 + 剪纸 / 版画感，暗色底、烛光暖黄高光。
- 房间板块：程序化 SVG（地板纹理 + 家具图标 + 门洞），每块房间一份配方，体积小、风格统一。
- 卡牌：HTML 卡面 + 图标（game-icons.net，CC BY 3.0，致谢页署名）。
- 探险者头像：程序化剪影 SVG。
- 音效：ZzFX 程序合成 + 少量 CC0 采样（开门、翻牌、心跳、尖叫）；BGM 一首探索、一首作祟。
- 字体：标题用开源衬线字体子集化（如思源宋体子集），正文系统字体。

## 9. 版权与命名

规则机制可以借用，**文字、角色、卡牌、剧本、美术、名称都必须原创**：
- 不用「山中小屋 / Betrayal / House on the Hill / 叛徒宝典 / 生存秘籍」等名称，界面里自创术语（例如「作祟」改为「异变」，两本书改为「叛徒密函 / 幸存者手札」）。
- 角色名字、背景、属性轨数值全部重新设计；房间里有辨识度的那些（随机传送房、滑道等）改名并调整细节。
- 粉丝 Wiki 和 GitHub 项目的内容数据不导入，只借鉴数据结构。
- 页面标注「受《山中小屋》启发的非官方同人作品，非商业」。

## 10. 风险

| 风险 | 对策 |
|---|---|
| 剧本规则千奇百怪，DSL 表达不了 | 先写 12 个剧本倒逼 DSL；实在表达不了的留「自定义钩子」逃生口（服务端 TS 函数），但要求先尝试 DSL |
| 隐藏信息泄露 | 唯一出口 `viewFor` + 属性测试 + 构建期检查剧本文本不进前端 |
| 作祟阶段 AI 太蠢 | 剧本自带 AI 提示；第一版接受「能完成目标但不聪明」 |
| 局时长 60–90 分钟，掉线概率高 | 托管、重连、快照恢复；DO 推迟更新避免发版断线 |
| 原创内容工作量大（45 板块 + 70 张卡 + 12 剧本） | 内容用数据表批量写；文案先简后精 |
| 免费 DO CPU 可能 10 ms | 结算是纯内存计算；AI 不做搜索，只做启发式 |
| 行写入额度 | 动作合批写，约 600 局/天 |

## 11. 需要你确认

1. **命名**：游戏名用原创名（推荐，比如「鬼宅」「夜宅异闻」），还是像魔法运动会那样沿用原名加非商用声明？剧本和卡牌内容无论如何都会原创。
2. **规则版本**：以第 3 版为准，第 2 版经典作祟检定作为可选项，可以吗？
3. **首批剧本数量**：12 个够不够？还是先 6 个尽快上线？
4. **美术**：程序化 SVG（体积小、风格统一，推荐），还是用 AI 生成位图插画（更有氛围，体积 5–10 MB）？
5. **人数**：3–6 人，允许「1 人 + AI」单机局吗？
6. **部署和仓库**：沿用同一个 Cloudflare 账号、先用 workers.dev；ghost 是否也单独建 git 仓库、要不要推到 GitHub？
